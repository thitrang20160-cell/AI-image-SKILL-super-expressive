# 检查、候选处理与复检

此流程执行用户授权的像素水印处理请求。元数据清理、处理器完成、官方复检、商品审核分别记录。不能因旧版 skill 尚未接入 remover 就停止排查；也不能把公开方法或本机安装成功写成实测去除成功。

## 从真实阳性开始

1. 保存原件和默认变体依据，记录 SHA-256。使用现有 C2PA 副本脚本处理容器；该步骤不改像素。
2. 用当前可用的官方检测渠道检查实际候选。OpenAI API 回执与 Google SynthID 网页人工回执分开保存。网页回执至少绑定文件 SHA、时间、实际可见结果、截图 SHA，保留 DOM 时也绑定其摘要。网页结果不冒充 API response。
3. `detected` 才进入已确认信号的处理链。错误、限额、未上传与不稳定 TrustMark 命中保持 `unknown`；先排查可恢复问题。既有阴性不能统计为去除成功。

当前实测例：2026-10-12 的 001-feature-2 工作稿在删除 C2PA 后，Google 页面仍显示 SynthID 检出并归因 OpenAI。002-material 两次返回服务错误，不能归为阴性。实图和哈希证据留在项目 audit，不把截图当成通用方法的有效性证明。

2026-10-13 已执行一张本机 SDXL 试验。Google 后检两次服务错误后，改用官方 OpenAI Verify 网页：相同处理前文件检出 SynthID，已保存处理后文件未检出。两份结果均绑定原文件、DOM 和截图 SHA；后续制作角色保真自查通过，新版链路仅确认该文件的支持信号已清除，不能覆盖其他文件或代替最终 SKU 审核。复用前看 [单图实际案例与恢复条件](watermark-pilot-20261013.md) 与 [备用官方网页实测](official-verify-ui-20261013.md)。

## 选择并运行候选处理

先确认用户已允许该执行工具，并核对代码来源、硬件、模型体积、工作目录与离线资源。遵守实际图像工具约束；用户未明确允许本机 Python/CLI 图像处理时，不静默切换。依赖、模型、临时文件和处理结果放用户指定盘，不修改正在使用的全局 Python 环境。

可选实验路线：`scripts/sdxl_watermark_candidate.py` 调用官方 Diffusers 的 SDXL 低强度 img2img。参考 [wmr 作者说明](https://github.com/froggeric/gemini-watermark-and-synthid-remover) 和 [Diffusers SDXL 文档](https://huggingface.co/docs/diffusers/api/pipelines/stable_diffusion/stable_diffusion_xl)。这会重建像素，并非解码后精准删除 SynthID 载荷；作者的小样本结果不能迁移成当前 OpenAI 商品图保证。官方文档明确 SDXL 默认可能另加传统水印，候选脚本显式使用 `add_watermarker=False`，仍须重新检测实际输出。

- 先固定一张当前阳性图与一组低强度参数，记录模型版本、依赖版本、方法代码 SHA、种子、步骤、耗时和输出 SHA。
- 默认试验是 strength 0.10、50 步、空提示词、guidance 0；这些是起始候选，不是已校准的通用配方。
- 保护原画幅和方向；脚本仅补至 8 像素网格，再裁掉新补边，不裁掉源内容。拒绝透明图和超出声明范围的输入，不静默压缩成小图。
- 原件不覆盖。模型已在本机时离线加载，检查模型文件 SHA；模型缺失或 CUDA 不可用时给出具体失败，不自动下载其他模型或退到未评估路线。
- MAE、PSNR 只量化改动，不能替代商品和文字审核。不要拷回原图大块像素或加边拼图去换阴性结果；这些可能保留水印或改变检测支持范围。
- 不根据一连串官方查询做无边界搜索。失败后依据实际症状决定一次有理由的修正、其他可行路线或外部条件；不反复运行相同失败设置、不对全批重复付费。

## 对最终字节复检

候选编码结束后检查容器，再检测最终字节。若重新导出或改图，旧检测回执立即失效。

优先使用与处理前一致的官方信号；保留 before / processing / after 三份原始证据。Google 或 [OpenAI Verify](https://openai.com/verify) 网页每次按当时 DOM 操作，逐文件上传并展开具体信号。切换通道时对处理前原文件再作同通道对照；不能仅凭“未发现 OpenAI 信号”的总体标题推断各项阴性。网页结果不伪装成 API 返回。新法律条款必须由用户确认，验证码按实际工具要求交给用户。不要调用网页内部私有接口，也不要把服务错误当“未检出”。遇到临时服务错误，可在有依据的间隔后重试一次；仍失败则保存现场，继续其他可执行步骤并查找能够覆盖同一信号的官方替代入口。

新增 `scripts/watermark_cycle.py` 是只读链路检查器：验证前后文件、处理回执、截图与审核哈希；核对实际像素确实发生变化。它不生成检测结果，不移除水印，不批准最终商品交付。

| 结果 | 状态 |
| --- | --- |
| 前图不是真实阳性 | baseline_unconfirmed，不计去除率 |
| 仅元数据变化，像素相同 | no_pixel_processing |
| 后图仍检出 | still_detected |
| 后图接口错误、限额或未查 | verification_unknown |
| 后图未检出，商品/文字变形 | rejected_quality |
| 后图未检出，保真审核尚未完成 | postprocess_quality_pending |
| 前图检出、实际处理、后图未检出且处理前后保真审核通过 | supported_signal_cleared_on_this_file，仅限该文件 |

保真审核检查构图、结构、数量/变体、精确文字、纹理/颜色与接触/手部，绑定源图和输出 SHA。这里核查的是本次处理造成的改动；源图原有的 SKU 审核 unknown、缺图、缺尺寸等问题仍需解决。一个成功样本不解除其他图片的检查要求。

遇到后检服务故障，完成本机容器检查、已接入的其他检测和原生尺度局部对照；只重试检测，不为获取结论重跑处理器。记录每次实际上传的回执，保留首次错误。没有界面依据时不推断账号限额或恢复时间。恢复后先检测已保存的相同 SHA 输出；只有实际改图才新建版本并使旧回执失效。

## 批次与交付

用户明确改变检测要求时，保存原话、适用批次与尚未检查数量，停止被跳过的检测和无必要处理。`unknown` / `not_performed` 不改成 `not_detected`，也不称水印全部去除。已明确接受剩余检测限制时可使用 `delivery_gate.py --accept-pixel-limitations`；该选项不能覆盖商品、文案、属性或元数据证据失败。继续图床和既有暂存记录回填，不反复要求用户接受已确认的限制。若当前版本仍有真实阳性，单独如实说明，不从“停止新检测”推导已处理阳性成功。

一张验证有效后，可以沿用有边界的方法处理已获授权的同批候选；仍逐文件保留回执和结果。不要处理已淘汰版本凑数量。记录尝试数、实际处理数、复检完成数、信号转阴数、保真通过数；分母只用真实阳性原件。

只有当前商品/文案审核、声明处理、必需像素检测和其他任务条件都满足时，才通过最终交付闸门。扩展 TrustMark 的不确定结果不由一次 SynthID 阴性覆盖。图床上传及暂存区写入继续遵守用户已确认的交付条件；不自动发布到沃尔玛。

成功与失败都沉淀：具体方法、版本、输入范围、失败现象、实测文件和有效边界进入项目案例。只有真实成功才写“本图已验证”；测试夹具、作者宣传、程序退出码和删掉 C2PA 均不计为水印去除成功。
