# 动作驱动场景与文字

用于需要强张力的广告、商业使用场景。先选择当前商品能支持的动作，再建立镜头和字物关系。纯白底主图、白底功能主图、尺寸和安装说明沿各自规则；这份方法不是所有图片的默认效果。

## 从动作组织空间

制作前把一句话写完整：`谁施力 → 在哪里接触 → 沿什么轨迹 → 产生什么可见结果 → 商品怎样仍被识别`。示例是手带动勺子，少量汤汁与食材顺勺端形成短弧线；不能暗示电炉自行把食物喷出、爆炸或增加了未核实功能。

1. **近景事件**：选少量最能表达动作的元素接近镜头，利用近大远小、边缘裁切、前后遮挡形成扑面感。只裁次要元素，不用成堆粒子填满画面，也不让道具成为被售商品。
2. **中景因果**：手、工具和作用对象的接触清楚，主要运动弧从实际施力处产生。关键动作冻结清晰，拖影只沿真实运动方向局部出现。
3. **商品锚点**：给主体保留足够尺寸及连续可辨的身份区域。本例产品位于下部；其他商品按实际机位选择位置，不硬套“永远放底部”。缩略图仍应看清卖的是什么，不能只剩品牌一角。
4. **共同机位**：相机滚转可以倾斜画面，产品、容器、台面和背景必须共享透视、光线与重力。滚转不等于把炉具悬空，锅底支撑也不能靠遮挡蒙混通过。

优先让尺度差、裁切、受力和材料表现构成张力。只有确有作用点才加短距离的雾、液滴或光迹；不要把全景锐化、强发光和随机漂浮当作动作。

## 让文字成为同一场景的一部分

文字数量和用途按 brief 决定，下列三种职责可选，不要求每张凑齐三句。

| 职责 | 位置与方向 | 核验 |
| --- | --- | --- |
| 主张词 | 大字位于中后层，被明确的前景物体局部穿过；基线借主运动轴形成势能 | 每个字母仍可辨，产品关键部件无遮挡 |
| 动作短语 | 较小，靠施力工具或动作发生处，沿其轴线/切线 | 方向与动作有关，不能只在空白处随机旋转 |
| 身份或局部说明 | 靠当前商品部位、接触位置或承载平面，较克制 | 沿产品边缘和贴面透视分开定义，不由旧案例继承参数 |

先画出这些关系再生成，不要把完成的动态底图重新压成“上标题、下卖点”模板。文字可以有不同方向，但每个方向都要有来源；字重、颜色、字号服务于主体和材料，不复制本例英文或橙灰配色。逐字检查成图；一体生图的文字标注为已烘焙位图。

## 跨类目只迁移关系

以下是改编提案，不是各类目已经通过的案例。

| 当前商品与动作 | 可迁移的张力 | 不能照搬 |
| --- | --- | --- |
| 厨具搅拌、盛取 | 勺端短弧、近景食材、中景锅与下部器具 | 无因果喷射、危险操作或自动烹饪宣传 |
| 挂烫/清洁头接触表面 | 衣料受力褶线、擦拭边缘、作用位置的局部轨迹 | 满画面碎屑、未经核实的除菌或前后效果 |
| 线材插入、弯曲 | 连续曲线跨层，短文案贴真实端点 | 飞散食材、随机电弧、旧 SKU 速率 |
| 美妆挤出、涂抹 | 用量、膏体弧面与手势引导文字 | 夸大用量、虚构功效或让膏体盖住包装身份 |
| 包袋提起、布料展开 | 提带张力、垂坠折线和前景布边 | 液滴飞溅、悬空失去受力来源 |

没有合适的动态动作时，改用材质受力、镜头尺度和空间文字，不强制造出飞跃事件。

## 认可样张与复用边界

配方：[cooking-kinetic-spatial.v1.json](recipes/cooking-kinetic-spatial.v1.json)。按需查看其 `motion-anchor` 和 `type-anchor`，分别对应无字动作版和文字交互版。商品身份仍来自本次原图。

用户先认可“画面对味”，再要求文字互动，最后授权“可以了 融入skill”。因此入库为 `user-style-approved`，只迁移动势、层次和文字方法。V3 独立审核的排版结论为 `pass`，整图结论仍为 `revise`：锅底承托不可确认、背景与主体共同机位不可确认。保留原始审核及实际文件哈希，不添加整图通过的 `audit_support`。

复用时分别审核：商品身份/材质尺度、接触与共同机位、动作因果、缩略图主体优先、字形与空间关系。样张的视觉认可不能解除这些检查，文字通过也不能升级底图准确性结论。
