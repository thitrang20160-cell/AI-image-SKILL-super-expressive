# 生图、审核、图床与表格

## 复用现有生图能力

实际制作时调用已安装的 `safesell-product-visuals`（生图skill），读取其 `AI生图SKILL.md`，再按本张职责读取7张套图、材质张力、动作场景、空间文字及审核分支。入口在同级 `safesell-product-visuals/SKILL.md`，也可由客户端已安装技能目录发现。先检索适用配方，只读最相关经验。

若该依赖移位，先查已安装技能和原目录的联接目标；不得假装已经跑过不存在的制作/后处理工具。这个编排技能不复制一份容易漂移的完整视觉配方。

默认7张职责固定顺序：主图、卖点1、卖点2、材质、场景1、场景2、尺寸。按用户要求可调整数量，调整后同步 manifest、审核和汇总表；不能只改表面图数。

## 本次认可的表现力

新制/返修的卖点、材质、场景图按生图skill v1.13 做非文字张力核验：商品动作、受力/接触、材料、机位/近远至少两项产生可见因果。忽略所有标题后若卖点不成立，就返修画面，不用放大字或换背景放行。主图与尺寸图按各自职责执行，不强制广告张力。整套工作中可先做一张无字构图校准图，复用其当前 SKU 几何关系；校准图不等于用户风格批准或整套通过。

- 先确定商品的真实作用关系，再设计强构图。机位、透视、尺寸对比、受力接触、动势和字物前后层共同形成张力。
- 材质图通过真实弯折、拉开、压住、卷曲或接触展示材料，不给硬质商品无依据的形变，也不虚构内部结构。
- 场景图要看见“商品—动作—结果”，而不只是手握商品。两张场景改变用途/镜头/动作，避免同一个布景换文字。
- 文字跟随商品方向、动作和层次，保持可读。生成文字乱码、断词或参数错误必须修复。强创意主要用于附图；主图保持当前类目允许的白底商品展示，不把广告样张直接当平台主图。
- 保持原 SKU 的轮廓、接头、拼缝、孔位、配件、颜色及件数。不得借张力改变实际规格、功能或包装内含物。

一套先验证有代表性的候选，用户已有风格认可就沿用，不反复要求重新选风格。后续迭代记录具体差异及被认可范围；审美认可只覆盖该范围。

## v1.11 稳定视觉执行入口

读取生图skill的 `references/stable-visual-production.md`，逐张保存新版brief、实际request和review。生成前运行 `visual_production_gate.py preflight`，实际调用同一份参数；全尺寸与缩略图对照原认可样张后运行 `review`。缺风格附件、文案遮错、风格未知或文件换版不放行。文字允许可辨的局部穿插，不把所有图降成平铺标题；主图和尺寸图按自身职责。

新增或重绘图片的批次设置 `visualGateRequired=true`，images逐张附 `visualPipeline.requestRef/reviewRef` 描述符。最终元数据/像素处理的哈希不同，再附含新版视觉结果的 `deliveryReportRef`。暂存/推送前的 `audit_batch.py` 会现场重读请求、审核、原始输入和文件哈希，不仅检查已保存的pass；[字段合同](data-contract.md)列出旧图复用与用户退回清单。

上传前先运行新版视觉审核闸门，再完成已有后处理/最终交付核对；写入暂存前运行批次闸门。只复用已认可且字节未变的旧图，不能用 `reuseExisting` 隐藏新图或用户退回图。缺项只阻塞对应图/写入，继续其他已授权制作；用户已有风格认可不重复确认。此维护未修改服务器接口，未经过上述调用者的API不会自动受到拦截。

## 逐张与跨图审核

每张保存：SKU、职责、原图依据、提示词/请求回执、输出路径、SHA256、商品/文字/使用动作观察、审核方式和 `pass / revise / unknown`。制作角色自查就写自查，不能伪称独立第三方复审；若用户要求独立审核，使用真正独立角色并提供原图和成图。

检查数量/配件、尺寸对象与单位、颜色、材质、结构、功能文案、使用方法、文字拼写和图中比例。数量错误、偷换颜色、虚构功能、错标尺寸或乱码不能被整体“好看”覆盖。

对整套再核对一次：七张都属于同一规格，主图数量不与五点冲突；场景道具不被当作包含物；尺寸图没有借用其他规格。型号/规格/文案发生变化时复核所有受影响图，不只改一张尺寸图。

## 去 AI 特征与水印

减少 AI 外观问题：修复重复零件、变形孔位、错误遮挡、手指异常、漂浮接触、塑料化金属、随机纹理和乱码。它是商品与画面审核，不是“AI检测分数”优化承诺。

用户请求水印检查/处理时，读取生图skill的 `references/watermark-check-remove-recheck.md` 和覆盖范围要求。分别保存：C2PA/EXIF 等容器数据、TrustMark、SynthID、其他明确检测器、候选像素处理及最终复检。C2PA清理不等于移除隐形水印，分类器也不是水印检测。

授权的像素处理先选当前阳性的1张保真试验，保留原件、参数、处理回执和最终字节。检测阴性之外还要重新核商品、文字及细节；不能把降低可辨识度或损坏商品作为“成功去除”。单图成功不覆盖整批，也不承诺所有算法和未来检测器均无水印。

新的检测渠道需要条款接受、登录或真人验证时，由用户完成相应步骤。某一检测服务失效不停止原图核对、文案、属性、其他图审核及图床准备。用户明确跳过剩余检测时保存原话和范围，未知保持未知，不重新索要密钥、不无限追测。

## 图床与最终字节

先找本项目已有服务器/上传服务和代码，使用已授权接口。当前项目已验证的公开图片域名为 `https://poa.safesellai.com/uploads/`；域名是现有证据，不是永远可用的硬编码前提。若不可用再排查或选择经用户授权的可用图床。

最终文件命名包含 SKU、职责和内容哈希，审核通过后上传；不要覆盖已经交付的旧 URL。GET最终URL，核 HTTP状态、实际图片可读性、文件类型及下载字节哈希。HEAD200、URL看起来正确或上传接口ACK不能替代这一步。

最终 manifest 绑定 `SKU + role + file + sha256 + url + hostedSha256 + review`。像素、尺寸、编码或元数据一旦改变，重新算哈希并对变更后的最终字节复核、上传；之后同步暂存和表格的全部相关 URL，不能混用旧图。

## 交付与对账

按照电子表格技能制作：商品汇总、原文案/属性、全部图片 URL 可分成不同用途的页。把售价、库存、数量和重量存为数值并格式化，时间可读，图片以 URL 字符串给用户，不用搜索页/预览页代替图片直链。

逐 SKU 对账原链接、锁定规格、主副图顺序、70张或本批实际总数、价格、库存目标及阶段状态。检查导出文件的实际单元格，查看每页渲染；对修改过的日期、长URL和错误说明检查是否截断或显示为日期序列号。不要在当前表里留下旧的“品牌待确认/售价未配置”等冲突状态。
