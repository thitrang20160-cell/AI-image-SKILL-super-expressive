# 速卖通产品精铺沃尔玛skill

把可核实的速卖通销售规格，做成有竞品依据、视觉表现力和准确商品信息的沃尔玛 listing，完成用户指定的暂存或实际推送，并用真实回执验收。只执行用户请求的阶段；已有合格文案、图片、URL 或暂存记录直接复用。

## 开始与恢复

1. 先读取当前批次清单、进度、原页证据、最新图片 manifest、暂存和官方回执，确定本轮要做哪些 SKU、哪个阶段。选品目标、试做数量和已完成数量分开记，不能用占位行凑数。
2. 从已有对话恢复国家/币种、价格条件、首单资格、规格选择、文案修改权限、目标店铺、售价和库存。已有授权不重复确认。缺失但影响执行的信息才询问，同时推进不依赖答案的工作。
3. 文件与资源保存到使用者指定的工作目录，技能安装位置可独立选择。不要把密钥、浏览器 Cookie、访问令牌或用户提供的秘密写进技能、日志和交付文件。
4. 同一批次的默认规格按第一次核实后锁定；刷新页面改变默认选项不构成换规格授权。来源 URL、选项标签、截图/DOM、观察时间与规格快照绑定同一 SKU。

本次已确认的选品和套图参数保存在 [项目预设](references/project-profile.json)。它是本项目配置，不代表沃尔玛通用规则；新任务的明确参数优先。店铺、品牌、制造商和售价不从旧商品继承。

## 新选品的执行顺序

用户于2026-10-14确定：**看流量 → 看利润（竞品对比） → listing → 图片 → 一致性审查 → 暂存/上架 → 官方回读验收**。对新候选先执行 [流量、利润与竞品闸门](references/traffic-and-profit.md)。流量和利润均通过，才投入新文案或生图；某项未知记待核，不因已有图片或低采购价跳过。恢复已完成阶段时保留成果；本规则不自动授权重定价、重发布旧商品。

速卖通销量是供应侧辅助证据，不能替代沃尔玛端的需求。定价使用[成本、竞争与成交机会曲线](references/adaptive-pricing.md)，原“成本加US$15”作为对照；在利润底线与竞争上限间寻找启动价，再用真实价格/转化数据校准。不能把假设最优点称为已验证最佳价，不能把加价写成净利润。首单促销与可重复补货成本分开。

## 必须贯穿全程的控制

- **先需求、再经济性、后制作。** 新SKU的两个前置闸门分别记录；佣金、物流、首单资格、件数、售价或配送承诺改变时重算利润，原结论不能直接复用。
- **事实先锁定。** 原链接所选规格控制数量、尺寸、颜色、材料、结构和功能。竞品内容、画廊其他规格和 AI 生成图不能成为本 SKU 的参数来源。
- **表现张力拉满，商品事实不变。** 用真实动作、尺度、机位、接触关系、空间文字和材质表现加强附图；主图另按当前美国站类目规则审核。用户认可审美不等于商品审核通过。
- **新图与返修执行视觉闸门。** 按生图skill v1.11实际绑定认可原图、商品原图和调用参数，预检、成图对照、定向返修后再审。新增/返修批次设置 `visualGateRequired=true` 并运行批次审计；旧图只按原认可manifest和相同字节复用，用户退回图不可复用。具体见[套图与审核](references/visuals-and-audit.md)。这些是技能调用入口的检查，不代表服务器API自动拦截。
- **文案已定就保留。** 用户只要求补属性或上架时，逐字保留标题、五点和描述；发现事实冲突先修复冲突证据及受影响项，不顺手重写全批。
- **未知、估算与实测分开。** 用户明确允许估算时记录字段范围、估算依据、单位及“未实测”；不能把估算写成供应商参数。估算不能代替检测、认证、生产商确认或真实保修承诺。
- **声明不冒充检验。** 卖家品牌、制造商和书面保修须有授权依据；Prop65 等合规字段依据实际资料或用户委托制定的适用卖家政策，不用一套默认值批量编造。政策选择、检测结论和实物标签分别核实。
- **检测状态如实保留。** 元数据、TrustMark、SynthID、AI 外观审核分开。未执行/错误/未知不等于阴性。用户跳过剩余检测时记清范围，停止被跳过的检查，继续其他已授权工作。
- **上架必须按授权阶段。** 生图或暂存请求不自动授权推送；已明确授权的指定店铺推送无需再次索要相同许可。不能将一店授权扩到另一店，不能修改全局凭据或品牌白名单来绕过闸门。
- **失败后修复再重试。** 保存原错误和现场，每次重试有新证据、修正数据或恢复条件；继续不受阻的工作。网络超时导致提交结果未知时先查 feed/ledger，不能重复上架。

## 可运行的只读核对

新选品可先运行只读利润与前置闸门核对，输入结构和限制见 [流量、利润与竞品闸门](references/traffic-and-profit.md)：

```text
python -X utf8 -B scripts/evaluate_selection.py --input ./work/input.json --report ./work/report.json
```

批次按 [数据合同](references/data-contract.md) 规范化后，在技能目录运行以下命令，或用审计器绝对路径：

```text
python -X utf8 -B scripts/audit_batch.py --batch ./work/batch.json --phase stage
python -X utf8 -B scripts/audit_batch.py --batch ./work/batch.json --phase push
python -X utf8 -B scripts/audit_batch.py --batch ./work/batch.json --phase acceptance
```

审计器检查规格、图序、文件/托管字节哈希、文案锁定、店铺和库存范围、促销条件以及回执状态。它只读文件、输出 JSON，不联网、不生图、不发布；记录中的人工观察和官方回执仍需实际取得，不由脚本创造。

## 结束与交付

交付表使用真实 SKU、原链接、锁定规格、流量证据、竞品同规格到手价、可持续成本、佣金/广告/售后假设、每单利润和闸门状态，再附当前阶段已完成的英文文案、属性、销售价、库存目标、图片URL及官方状态。未通过前置筛选的SKU不为填满表格而制作后续内容。按电子表格技能导出、检查数值及全部 URL，并查看实际渲染。

区分“候选”“已完成文案”“图片通过”“图床核对”“已暂存”“已推送”“GTIN 豁免获批”“建品成功”“可售”。`ACK`、Feed `PROCESSED`、豁免 `APPROVED` 都不能单独替代逐件成功和目录/库存读回。

有实际外部等待时说明准确恢复条件和已完成部分；自动续跑按用户请求安排。用户选择手动继续时只保存续跑入口，不创建定时任务，也不声称会后台持续工作。此次建技能不触发原批次重新提交。
